# Инженерные рекомендации по результатам Главы 4

Дата подготовки: 2026-05-11.

Рекомендации основаны на финальных RawLogs, обработанных таблицах и графиках. Они предназначены для практического раздела ВКР и не заменяют требования конкретного промышленного проекта.

## Выбор периода и deadline

Для VPLC не следует автоматически переносить малые периоды цикла без проверки хвостов распределения. В финальной серии при `T0 = 10 ms` наблюдались превышения deadline и рост `Q99.9`:

- `VPLC_L0_IDLE_10_20`: `Q99.9 = 27 ms`;
- `VPLC_L1_LIGHT_10_20`: `Q99.9 = 30 ms`.

Для задач, чувствительных к единичным выбросам, полезно оценивать не только среднее и медиану, но и `Q99`, `Q99.9`, `Rmiss`, `Lburst`.

## Проверка нагрузки

Stress-режим полезен как обязательный элемент методики: он показывает поведение около границы применимости. В текущих данных оба объекта имеют deadline miss в режиме `L3_STRESS_75_80`, поэтому такой режим удобен для сравнения устойчивости на границе.

Для эксплуатационного выбора режима лучше использовать запас относительно deadline. Например, режим `L3_HIGH_75_100` менее жёсткий, чем `L3_STRESS_75_80`, и лучше показывает поведение при наличии практического резерва.

В принятой шкале `L3_STRESS_75_80` имеет роль `stress_boundary`. Поэтому RED-статус stress-режима не следует переносить на рабочие режимы как общий запрет применения платформы; он фиксирует поведение при намеренно ужесточённом deadline.

## Организация измерений

Для дальнейших проектов рекомендуется сохранять:

- не менее 5 повторов на режим;
- не менее 1000 строк на повтор;
- единый набор Mode для HW PLC и VPLC;
- неизменяемые RawLogs;
- отдельные обработанные таблицы и SummaryCards.

Технические прогоны допускается хранить отдельно, но не смешивать с финальной серией.

## Применение VPLC

По текущим данным VPLC можно рассматривать для задач, где:

- допустимы проверенные периоды цикла и запас по deadline;
- критичны воспроизводимость и наблюдаемость программного стенда;
- допускается предварительная нагрузочная проверка конкретного режима;
- оценка проводится по хвостам распределения, а не только по среднему времени цикла.

Для задач с жёстким real-time deadline без запаса требуется отдельное подтверждение на целевой конфигурации.

## Применение HW PLC

HW PLC в финальных данных показал стабильное поведение в режимах L0, L1, L2 и L3_HIGH без deadline miss. Это подтверждает его роль как базовой аппаратной точки сравнения для методики.

Stress-режим S7 также показал превышения deadline, что важно для текста ВКР: даже аппаратный контроллер при специально выбранной нагрузке и жёстком пороге может перейти в пограничную область.
