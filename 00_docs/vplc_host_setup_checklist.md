# Чек-лист подготовки VPLC_HOST

Документ описывает практический порядок выполнения пунктов 3-7 этапа 4.0:

3. установить Ubuntu 22.04 LTS на mini-PC;
4. настроить статический IP mini-PC;
5. проверить связь `ENG_NODE <-> VPLC_HOST <-> HW_PLC`;
6. установить SSH и базовые утилиты;
7. снять первый конфигурационный снимок mini-PC.

Цель чек-листа - выполнить первичную подготовку mini-PC воспроизводимо и без потери трассируемости для ВКР.

## 0. Исходные решения

| Параметр | Принятое значение |
|---|---|
| Узел | `VPLC_HOST` |
| Аппаратная платформа | mini-PC MLLSE G2 Pro |
| CPU | Intel Processor N150 |
| RAM | 12 GB |
| SSD | M.2 512 GB |
| Целевая ОС | Ubuntu 22.04 LTS x86_64 |
| Планируемое имя хоста | `vplc-host` |
| Стендовый IP | `192.168.10.20` |
| Маска | `255.255.255.0` / `/24` |
| Шлюз в измерительном сегменте | не используется |
| DNS в измерительном сегменте | не требуется |
| Основной каталог артефактов | `D:\HOME_BASE\VKR_Experiments` |
| Начальный ManifestCfg | `configs/stand_manifest_initial.yaml` |

## 1. До установки ОС

- [ ] Проверить, что текущий рабочий каталог зафиксирован: `D:\HOME_BASE\VKR_Experiments`.
- [ ] Проверить, что создан начальный ManifestCfg: `configs/stand_manifest_initial.yaml`.
- [ ] Подготовить установочный носитель Ubuntu 22.04 LTS x86_64.
- [ ] Подключить monitor/keyboard/mouse или иной удобный способ первичной установки.
- [ ] Убедиться, что на этапе установки допустимо временное подключение к интернету.
- [ ] Зафиксировать в заметках фактическую модель mini-PC, если она видна в BIOS/UEFI.
- [ ] По возможности сфотографировать или записать версию BIOS/UEFI.

## 2. Установка Ubuntu

Рекомендуемые решения для первичной установки:

- язык установщика: любой удобный, но системные имена лучше задавать латиницей;
- hostname: `vplc-host`;
- пользователь: задать постоянного оператора стенда;
- разметка SSD: использовать весь диск, если на mini-PC нет данных, которые нужно сохранить;
- обновления во время установки: допустимы только на этапе подготовки, не во время измерений;
- сторонние драйверы: включать только при реальной необходимости для сетевого оборудования или видеовывода.

После завершения установки:

- [ ] Перезагрузить mini-PC с установленной ОС.
- [ ] Войти под созданным пользователем.
- [ ] Проверить, что система загружается без установочной флешки.

## 3. Первичная проверка ОС

Выполнить на `VPLC_HOST`:

```bash
hostnamectl
uname -a
lscpu
free -h
lsblk
ip addr
ip route
```

Зафиксировать факты для последующего обновления ManifestCfg:

- [ ] фактическое имя хоста;
- [ ] версия Ubuntu;
- [ ] версия ядра Linux;
- [ ] архитектура;
- [ ] имя сетевого интерфейса;
- [ ] MAC-адрес сетевого интерфейса;
- [ ] наличие/отсутствие шлюза по умолчанию;
- [ ] фактическая структура диска.

## 4. Настройка статического IP

Целевое значение для `VPLC_HOST`:

```text
IP:      192.168.10.20
Mask:    255.255.255.0
Gateway: none
DNS:     none for isolated measurement segment
```

Перед правкой сетевой конфигурации определить имя интерфейса:

```bash
ip link
```

После настройки проверить:

```bash
ip addr
ip route
```

Критерии готовности:

- [ ] интерфейс имеет адрес `192.168.10.20/24`;
- [ ] адрес получен не через DHCP;
- [ ] лишний шлюз по умолчанию отсутствует в измерительном сегменте;
- [ ] настройка сохраняется после перезагрузки.

## 5. Проверка связи стенда

С `ENG_NODE` проверить:

```powershell
ping 192.168.10.20
ping 192.168.10.10
```

С `VPLC_HOST` проверить:

```bash
ping -c 4 192.168.10.30
ping -c 4 192.168.10.10
```

Где:

- `192.168.10.10` - `HW_PLC`;
- `192.168.10.20` - `VPLC_HOST`;
- `192.168.10.30` - `ENG_NODE`.

Критерии готовности:

- [ ] `ENG_NODE` видит `VPLC_HOST`;
- [ ] `ENG_NODE` видит `HW_PLC`;
- [ ] `VPLC_HOST` видит `ENG_NODE`;
- [ ] `VPLC_HOST` видит `HW_PLC`;
- [ ] фактические адреса совпадают с `configs/network_plan.md` или отклонения явно зафиксированы.

## 6. SSH и базовые утилиты

На `VPLC_HOST` установить минимальный набор:

```bash
sudo apt update
sudo apt install -y openssh-server curl wget git htop sysstat net-tools ethtool lshw
```

Проверить SSH:

```bash
systemctl status ssh
ss -tulpn
```

С `ENG_NODE` проверить подключение:

```powershell
ssh <user>@192.168.10.20
```

Критерии готовности:

- [ ] SSH-сервис установлен;
- [ ] SSH-сервис запущен;
- [ ] вход с `ENG_NODE` работает;
- [ ] установлен минимальный набор диагностических утилит;
- [ ] факт установки зафиксирован в журнале этапа.

## 7. Первый конфигурационный снимок

После установки ОС, сети, SSH и базовых утилит снять первый снимок:

```bash
date --iso-8601=seconds
hostnamectl
uname -a
lscpu
free -h
lsblk
ip addr
ip route
ss -tulpn
systemctl list-units --type=service --state=running
dpkg -l | grep -E 'openssh|podman|vplc|masc|sysstat|stress'
```

Рекомендуемое имя артефакта после переноса в рабочий каталог:

```text
configs/vplc_host_config_snapshot_2026-04-25_initial.txt
```

Если снимок делается в другую дату, использовать фактическую дату.

После переноса снимка в `VKR_Experiments` обновить:

- [ ] `configs/stand_manifest_initial.yaml`;
- [ ] `00_docs/stage_4_0_log.md`;
- [ ] при необходимости `configs/network_plan.md`.

## 8. Что не делать на этом шаге

- [ ] Не устанавливать Podman до фиксации первого снимка ОС и сети.
- [ ] Не устанавливать MASC/VPLC до завершения пунктов 3-7.
- [ ] Не запускать тестовые прогоны.
- [ ] Не записывать KPI, графики или выводы по детерминизму.
- [ ] Не считать ping-проверку экспериментальным результатом.

## 9. Готовность к следующему этапу

К пункту 8 этапа 4.0, установке Podman, можно переходить только после того, как:

- [ ] Ubuntu 22.04 LTS установлена;
- [ ] `VPLC_HOST` имеет статический адрес `192.168.10.20/24`;
- [ ] SSH-доступ с `ENG_NODE` работает;
- [ ] связь с `HW_PLC` проверена;
- [ ] первый конфигурационный снимок сохранён;
- [ ] ManifestCfg обновлён фактическими данными;
- [ ] журнал этапа 4.0 обновлён.
