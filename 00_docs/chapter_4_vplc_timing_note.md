# Примечание для Главы 4: источник времени VPLC

Дата фиксации: 2026-05-09.

## Контекст

В практической части ВКР сравниваются аппаратный PLC Siemens S7-1200 и VPLC в одинаковых режимах нагрузки `Mode`. Для S7-1200 в программе подтверждён внутренний источник времени на базе `RD_LOC_T().NANOSECOND`, поэтому для аппаратного PLC рассчитываются `Tper`, `Jper`, `deadline_miss` и производные KPI.

Для VPLC Studio/VPLC runtime 2.10.0 на момент практического этапа 4.0 не подтверждена доступность ST-функции внутреннего timestamp, monotonic tick, системного времени или длительности цикла внутри ST-кода. Встроенная документация VPLC Studio 4.1.3 beta не содержит опубликованной функции такого назначения.

## Практическое решение

Методика эксперимента не переписывается. В Главе 4 добавляется практическое примечание об ограничении источника данных VPLC:

- для Siemens S7-1200 анализируется фактический период цикла `Tper`, полученный из внутреннего timestamp PLC;
- для VPLC анализируется наблюдаемый runtime-показатель `cycle_exec_ms`, получаемый из штатного `vplc status` как поле `Длительность цикла (ms)`;
- `cycle_exec_ms` не отождествляется напрямую с `Tper`, пока производитель не подтвердит семантику этого поля;
- VPLC-строки помечаются `timestamp_source=host_log` и не используют поля `Tper/Jper/deadline_miss` как внутренне подтверждённые значения цикла.

## Допустимость сравнения

Сравнение по методике остаётся допустимым, если в тексте и таблицах явно разделены два класса результатов:

- строгие timing KPI аппаратного PLC: `Tper`, `Jper`, `deadline_miss` и производные показатели;
- наблюдаемые runtime status KPI VPLC: `cycle_exec_ms`, `cycle_exec_over_threshold`, `Rover_exec`, `Lburst_exec`.

Такое сравнение позволяет оценивать поведение систем в одинаковых режимах нагрузки, устойчивость к росту нагрузки и наличие хвостовых выбросов. При этом оно не является прямым сравнением `Tper` Siemens S7-1200 с `Tper` VPLC, так как для VPLC внутренний источник периода цикла не подтверждён.

В выводах запрещается подменять `cycle_exec_ms` полем `Tper`. Корректная формулировка: для S7 сравнивается внутренне измеренный период цикла, для VPLC - наблюдаемая длительность выполнения программы по данным runtime status.

## Рекомендуемая формулировка

```text
Для аппаратного PLC S7-1200 период цикла Tper рассчитывался по внутреннему timestamp, фиксируемому в программе. Для VPLC в используемой версии среды не была подтверждена доступность ST-функции внутреннего timestamp. Поэтому в практической части для VPLC использовался показатель cycle_exec_ms, получаемый из штатного runtime status VPLC как "Длительность цикла (ms)". Данный показатель рассматривается как наблюдаемая длительность выполнения программы VPLC и используется для оценки стабильности и хвостовых выбросов в одинаковых режимах нагрузки. Прямое отождествление cycle_exec_ms с Tper не выполняется.
```

## Последствие для таблиц и выводов

В производных таблицах и summary cards следует разделять:

- S7 metrics: `Tper_*`, `Jper_*`, `deadline_miss`, `Rmiss`, `Lburst`;
- VPLC status metrics: `cycle_exec_*`, `cycle_exec_over_threshold`, `Rover_exec`, `Lburst_exec`.

В сравнительных выводах допустима формулировка:

```text
Сравнение выполнено по одинаковым режимам нагрузки. Для S7 анализируется внутренне измеренный период цикла, для VPLC - наблюдаемый runtime-показатель длительности выполнения программы. Различие источников времени учитывается как ограничение практического эксперимента.
```
