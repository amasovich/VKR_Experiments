# Ограничения эксперимента и применимости выводов

Дата подготовки: 2026-05-11.

Документ фиксирует ограничения, которые нужно явно указать при написании Главы 4.

## Ограничения стенда

Результаты относятся к конкретной конфигурации стенда, версии VPLC, проектам workload и условиям запуска. Их нельзя автоматически переносить на все VPLC, все аппаратные PLC или другие хостовые ОС без повторной проверки.

## Ограничения временной базы

Для HW PLC использовался внутренний источник времени Siemens через программу SCL. Для VPLC финальная серия использует `_milliseconds_from_start_`, подтверждённый по обновлённой документации и техническому timing probe.

Измерения сравнивают наблюдаемое поведение цикла в рамках доступной временной базы. Они не являются низкоуровневым профилированием планировщика ОС, runtime VPLC или аппаратного таймера.

## Ограничения нагрузки

Workload является синтетическим и детерминированным. Он нужен для сопоставимого нагружения циклов S7 и VPLC, но не моделирует полностью конкретный промышленный объект управления.

Режимы L0, L1, L2, L3_HIGH и L3_STRESS выбраны как экспериментальная матрица. Выводы по другим нагрузкам требуют дополнительных прогонов.

## Ограничения порогов GREEN/YELLOW/RED

Профиль `configs\mode_thresholds.yaml` зафиксирован как `calibrated_for_vkr_chapter_4` для класса умеренно критичного циклического контура управления / технологической автоматики без функций ПАЗ/SIL. Поэтому `processed_tables\comparison\threshold_status.csv` и SummaryCards можно использовать как калиброванную классификацию в рамках данной ВКР.

Численные KPI рассчитаны из RawLogs и не зависят от выбора цветового статуса. Цветовая шкала является инженерной интерпретацией для выбранного класса сценария, а не универсальной нормой для всех типов технологических процессов.

Для `L3_STRESS_75_80` статус RED трактуется отдельно: это не ошибка эксперимента, а признак достижения или пересечения границы устойчивости в stress-сценарии с намеренно жёстким deadline.

## Ограничения статистики

Для каждого режима выполнено 5 повторов по 1000 строк. Этого достаточно для практической демонстрации методики и расчёта выбранных KPI, но не заменяет длительные ресурсные испытания, суточное наблюдение или анализ редких событий с очень малой вероятностью.

## Ограничения интерпретации причин

По текущим данным можно сравнивать `Tper`, `Jper`, `deadline_miss`, `Rmiss`, `Lburst`, повторяемость и качество данных. Нельзя строго доказать внутреннюю причину каждого выброса без дополнительных трассировок ОС, runtime VPLC и нагрузки хоста.
